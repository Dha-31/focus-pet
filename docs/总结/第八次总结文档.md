## 一、项目回顾：我们在做什么

**Focus Pet —— 陪你学习、也监督你学习的桌面养成宠物。**

它不是一个普通桌宠：它把"学习监督"和"陪伴养成"揉进一只会动、会生气、会撒娇的小猫里。
你专心学习时它在旁边卖萌、打盹、攒好感；你一摸鱼它就一点一点变生气，用分级阻断把你拉回来；
它还会打工赚币、买家具、装饰自己的空间、拿每日/每周/每月奖章——把枯燥的自律变成"养宠物"。

从 v1 到 v4.0.4，项目经历了 8 个大阶段、几十次迭代，最终从"纯 Python 命令行小工具"
长成了"Electron 透明 HTML 桌宠 + 浏览器扩展 + 本地 AI 感知"的完整桌面应用。

## 三、当前版本功能全景（v4.0.4）

### 监督与阻断
- 活动窗口检测 + 浏览器扩展 URL 级黑白名单 + 教宠物（误判可纠正，桌宠会记住）
- 本地截图画面分析（OCR/图案/颜色/ML）作为兜底，**可强制拦截**，用户可点"这是学习页面"解封
- 情绪温度计逐级变生气（4 档）、分级阻断（提醒→遮挡→提示关闭），考试/日常/轻松/自定义四档模式
- 学习计时、番茄钟、退出承诺锁、防绕过扣币扣好感

### 桌宠体验（Electron HTML）
- 透明 + 置顶 + 鼠标穿透的 HTML 小猫：呼吸、眨眼、情绪、抖动、打盹、踱步、眼睛追踪
- **说话气泡**：紧贴脑袋右侧、最大字号 12px、随迷你模式缩放、绝不两字换行、不遮脸
- 双击摸头（冒爱心+脸红+眯眼，带冷却）、投喂、每日打卡
- 右键菜单（分类分组、限高滚动）、系统托盘（退出=最小化到托盘）、开机自启、迷你模式、免打扰

### 养成与空间
- 专注币经济：学习赚币、投喂/购物花币、每日打卡连签奖励
- 奖章系统（苹果健身 App 风格）：每日/每周/每月 9 枚 + 顶部进度条
- 成就系统：11 个里程碑徽章
- 我的空间：温馨小屋 / 星空田野 / 海边 / 森林 四张地图，家具 110px 自由拖拽、猫 110px 最上层
- 商店：家具按地图分类（含 6 件露营家具），分地图购买/摆放，价格可配置

### 全部窗口 HTML 化
- 设置 / 黑白名单（加宽 1500）/ 帮助中心 / 成就（奖章墙）/ 学习报告 / 商店 / 我的空间 共 7 个 HTML 窗口
- Tk 仅作为 Electron 不可用时的回退渲染器

## 五、关键技术决策与踩坑记录（最重要的经验）

1. **渲染方案三选一，最终选 Electron**
   - pywebview / CEF 在 Python 3.14 下不可行；Tk 透明与动画能力有限。
   - **Electron 43.2.0** 透明桌宠方案胜出（学 Open-LLM-VTuber 桌宠模式），`main.py` 优先 Electron、失败回退 Tk。

2. **透明窗口 + 无独显 = 软件渲染，踩了两个大坑**
   - 必须 `app.disableHardwareAcceleration()` 才能真透明（否则黑屏）。
   - **合成层坑**：气泡若被 `will-change/translateZ` 提升成独立合成层，软件合成器会把它丢弃（屏幕上看不见）；普通 div（如右键菜单）则正常。**教训：透明窗口里别随便做层提升。**
   - **宽度坑**：绝对定位气泡放进 150px 小区域会因"可用宽度=容器宽-左偏移"而一行只剩一两个字、变成细长白柱。**教训：定位前先算可用宽度。**

3. **"没说话"的真相往往是触发条件**：`main.py` 启动提醒只在"今天未打卡"时触发，用户打过卡后启动就一句不说 → 后来改为**无条件启动问候**。

4. **分界线作用域 bug**：`fy` 在 `draw()` 局部定义却被 `drawWallDeco()` 引用，导致星空场景的山丘一直画不出来（报错被吞）。**教训：跨函数共享的常量提到模块级。**

5. **Live2D 评估后弃用**：Cubism 运行时加载问题 + 用户上传任意图片难以自动绑骨骼 + 云端模型体积问题 → 按用户决定先放后，保留经典/HTML 两种形象模式。

6. **主动借鉴优秀案例**：从 Open-LLM-VTuber 借鉴了桌宠窗口方案（透明/穿透/托盘）；GitHub 调研报告驱动了渲染选型。**先调研再动手，少走弯路。**

7. **功能做减法**：按用户反馈删除了打工、摄像头监督、饰品、小游戏、AI 对话——"学习软件，不要小游戏"；用户明确"先体验稳定版，后续版本再扩展"。

8. **隐私承诺贯穿始终**：摄像头/截图本地处理不上传；浏览器扩展只连 127.0.0.1；数据目录 `%LOCALAPPDATA%\FocusPet` 稳定化。

## 六、测试与质量保障

- 每次改动：`py_compile` + `python main.py --headless-check` + JS 语法校验 + Electron 渲染冒烟（截图/像素验证）
- 关键 UI 问题（气泡渲染、层级、森林场景）都用**真实屏幕截图 + 像素分析**验证后才交付
- 改一处必查影响面：气泡位置连带宽度/避让，分界线改动连带星空/森林两场景
- 临时诊断代码交付前全部清理（本次已清理 90+ 个调试文件）

## 七、已知限制与尚未完成

1. **打包分发未做最终验证**：`tools/build_exe.py --windowed` + Electron 资源打包已就绪，正式客户端尚未产出（当前用 `start_pet.bat` / `demo_electron_pet.bat` 运行源码版）。
2. **帮助中心版本号**：`core/help_data.py` 的 `VERSION` 仍是 `4.0.1`，发版前需更新。
3. **Live2D / Q 版形象生成**：暂缓（骨骼模型体积、上传图片自动绑骨难度、云端模型成本）。
4. **AI 对话**：用户评估后认为当前不需要，暂缓。
5. **浏览器扩展上架**：打包 zip 已就绪，待用开发者账号提交 Edge/Chrome 商店。
6. **Electron 运行时（约 137MB）不提交 git**，换机器需重新下载。
