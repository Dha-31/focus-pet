### 3. 透明问题排查全过程（核心记录）
现象：用户反馈 pywebview 窗口背景黑底 → 修复后白底 → 始终不透出桌面。

排查与尝试（均记录，避免重蹈）：
1. `transparent=True + frameless=True`：黑底。
2. 源码分析：pywebview 只把 WebView2 `DefaultBackgroundColor` 设为透明，**承载窗口（WinForms Form）本身未透明**。
3. 在 UI 线程补设 `Form.BackColor=Transparent` + WebView2 透明：黑→白（Form 层透明了，但 WebView2 合成层仍不透）。
4. `WS_EX_NOREDIRECTIONBITMAP` 窗口样式：`SetWindowLong/SetWindowLongPtr` 被系统拒绝（WinForms 托管窗口，lasterr=0 不生效）。
5. `TransparencyKey` 颜色键：对 WebView2 的 DirectComposition 层无效。
6. 禁用 GPU（`--disable-gpu --disable-gpu-compositing`）：内容渲染异常（整窗灰）。
7. 客观检测受限：ImageGrab / GetPixel / PrintWindow 均抓不到 WebView2 合成内容（DirectComposition），透明只能靠人眼确认。

**结论**：pywebview（WinForms+WebView2）在无独立显卡机器上透明不可行，属渲染引擎 × 硬件的兼容限制，非改代码可解。

### 4. CEF 方案尝试与结论
- 用户选择装 CEF。已安装 `cefpython3==66.1`（65.8MB）。
- **堵死**：cefpython3 是 2020 年老组件，最高支持 Python 3.8，项目为 Python 3.14.5，报 `Python version not supported: 3.14.5`。
- 结论：CEF 后端在当前 Python 环境下不可用，放弃。

### 5. Open-LLM-VTuber 借鉴分析（关键方向修正）
- 该项目的「透明背景 + 全局置顶 + 鼠标穿透」桌宠模式由 **Electron**（`transparent/frameless/alwaysOnTop` + `setIgnoreMouseEvents`）实现。
- **结论修正**：HTML 桌宠要真透明，正路是 Electron / Tauri（BongoCat 亦用 Tauri），pywebview 不再考虑。
- 其余可借鉴：点击/拖拽区分（时间+距离阈值 → hitTest → 区域动作）、鼠标悬停同步、`model_dict.json` 配置数据化（kScale / emotionMap / tapMotions）、情绪→表情标签驱动、官方 Cubism 框架、全程容错。
- 详见 `docs/Open-LLM-VTuber借鉴分析.md`。

### 6. Tk 版气泡同步修复（可立即交付）

## 三、解决方法路径总结（本次核心）

```
v4.0.4 交互界面升级
 ├─ 路线1：HTML 界面 + 真透明
 │    ├─ pywebview(WebView2)：透明在无独显机器上不可行 ❌（黑/白底，已探明）
 │    ├─ CEF：cefpython3 不支持 Python 3.14 ❌
 │    └─ Electron / Tauri：透明+置顶+鼠标穿透成熟 ✅（借鉴 Open-LLM-VTuber / BongoCat）
 │         → 结论：以后做 HTML 桌宠走 Electron/Tauri（工作量≈重写，另行立项）
 ├─ 路线2：Tk 增强（当前 v4.0.4 落地）
 │    ├─ 透明：Tk `-transparentcolor` 稳定 ✅
 │    ├─ 气泡/字号/换行/窗口加宽：已修 ✅
 │    └─ 借鉴落地：情绪→表情映射数据化、点击区域→动作(摸头/戳身体)、hover 交互
 └─ 远期：真 Live2D → 官方 Cubism 框架 + model_dict.json 数据化 + 解决黄猫美术资产
```
